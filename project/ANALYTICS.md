# Статистика сайта

Статистика появляется после подключения Cloudflare D1 и публикации обновлённых Worker и сайта. Прошлые посещения и прослушивания восстановить нельзя. До подключения базы админка показывает, что статистика не настроена; работа сайта и медиа не зависит от D1.

## Подключение в Windows

Используйте существующую папку проекта с вашими `settings.json`, `worker/wrangler.jsonc` и `credentials/`. Нужны Node.js 24.12.0 или новее и вход в текущие аккаунты Cloudflare и Firebase. Не заменяйте рабочую конфигурацию примером. Сначала сделайте резервную копию папки проекта.

В PowerShell выполняйте команды по одной. При ошибке исправьте её до следующего шага:

```powershell
Set-Location 'C:\eduard-site\project'
npm.cmd ci --no-audit --no-fund
npm.cmd run doctor -- --strict
npm.cmd run setup:analytics
```

Последняя команда только показывает план: не вызывает Cloudflare и не меняет файлы. Следующая команда выполняет настройку D1:

```powershell
npm.cmd run setup:analytics -- --apply
```

Она находит или создаёт `eduard-shilov-analytics` в аккаунте из текущего `worker/wrangler.jsonc`, добавляет привязку `ANALYTICS_DB`, ограничитель частоты и расписание очистки, затем применяет SQL-миграции. Если привязка уже существует, используется её база. Повторный запуск безопасен: база и расписание не дублируются, применённые миграции пропускаются. После прерванной миграции повторите ту же команду.

Скрипт сохраняет комментарии JSONC, текущие переменные, секреты и посторонние привязки. Первая версия конфигурации до изменения сохраняется в `credentials/wrangler-before-analytics.jsonc`; повторный запуск не перезаписывает эту копию. Серверные секреты не переустанавливаются. Эта команда ещё не публикует Worker или Hosting.

Проверьте сборку и локальный runtime:

```powershell
npm.cmd test
npm.cmd run test:analytics:runtime
npm.cmd run build
npm.cmd run check
npm.cmd run bundle:worker
```

Затем опубликуйте обе части с существующими настройками:

```powershell
npm.cmd run deploy:worker -- --apply
npm.cmd run deploy:hosting -- --apply
npm.cmd run verify:live
```

Войдите владельцем в админку и откройте «Статистика». Пустой отчёт после подключения ожидаем: данные появятся после новых событий посетителей, разрешивших аналитику. Периоды 7, 30 и 90 дней включают сегодняшний день, границы дней — UTC. `startedAt` означает день первого принятого события.

## Что означают цифры

| Показатель | Что учитывается |
| --- | --- |
| Визиты | Случайные сессии вкладки с просмотром публичной страницы. Это не число людей или уникальных посетителей. После 30 минут без событий создаётся новая сессия. |
| Просмотры | Открытия разрешённых публичных страниц при включённой аналитике. Админка исключена. |
| Прослушивания | Не менее 30 секунд фактического воспроизведения; для короткого трека — не менее 90% длительности. Паузы, буферизация и перемотка не добавляют время. |
| Дослушивания | Достигнут конец трека и воспроизведено не менее 90% длительности. Требуется уже принятое прослушивание. |
| Скачивания | Запросы или нажатия скачивания. Завершённую загрузку и сохранение файла на устройстве браузер не подтверждает. |
| Интерес к выступлениям | Нажатия отмеченных ссылок предложений. Это не отправленные заявки и не заказы. |

Прослушивание, дослушивание, скачивание одного трека и нажатие одного предложения учитываются по одному разу за сессию. Повторная доставка того же события не увеличивает счётчики. Учитываются только опубликованные треки; в отчёте могут остаться накопленные данные скрытых или удалённых треков.

Сбор работает только после отдельного согласия на аналитику. DNT и GPC запрещают сбор даже при сохранённом согласии. При отзыве согласия отправка прекращается и идентификатор сессии удаляется из браузера. Поэтому отчёт охватывает только часть аудитории; сетевые ошибки, блокировщики и ограничения также могут уменьшить цифры.

В D1 нет имён, email, IP-адресов, полного URL с параметрами или постоянного идентификатора посетителя. Случайные идентификаторы событий и сессий записываются как SHA-256 для устранения повторов. Для кратковременного ограничения частоты Worker использует хеш IP с датой; в D1 он не сохраняется. Доступ к отчётам требует действительного Firebase-токена владельца.

## Лимиты и хранение

По умолчанию принимается не более **5000 событий за день UTC** на весь сайт и **200 событий за сессию**. Дополнительный ограничитель допускает до 60 запросов в минуту на ключ в Cloudflare. При достижении дневного лимита отчёт показывает ограничение; отклонённые события не превращаются в просмотры. `ANALYTICS_DAILY_LIMIT` меняет дневной порог в пределах 100–20000, если это необходимо; настройка сохраняет уже заданное значение.

Журнал событий и сессий хранит текущую и предыдущую даты UTC, суточные агрегаты — до 366 дат. Очистка выполняется ежедневно в **03:17 UTC**, а также при запросе отчёта владельцем. Расписание начнёт работать после публикации Worker. База и её привязка необязательны: без `ANALYTICS_DB` сбор и отчёты возвращают явное состояние «не настроено».

Локальные проверки не создают облачную базу и не доказывают публикацию. `test:analytics:runtime` выполняет настоящие SQLite-триггеры и D1-запросы в локальном workerd; боевое подключение проверяется после команд настройки и публикации.
