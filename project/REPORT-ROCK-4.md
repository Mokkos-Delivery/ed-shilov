# ROCK 4 — 2026-11-18-rock-4

Исправление ожидания между нажатием Play и началом аудио/видео. Рабочие Firebase/Cloudflare не публиковались из этой среды; время начала воспроизведения на eduardshilov.com не измерено.

- Плеер выбирает готовую MP3-копию ДО первого запроса. В «Авто» предпочитает 192 kbps, при экономии трафика/медленной сети — 128 kbps; если доступна только одна копия, использует её. Без копий сохраняет исходник. Явный выбор оригинала сохраняется. Ранее облегчённая копия выбиралась только после успешного запуска оригинала.
- Аудио/видео используют прямой HTTPS-адрес Worker, исключая промежуточный redirect с домена сайта. URL воспроизведения имеют `stream=1`; скачивание оригинала остаётся отдельным режимом.
- При наличии видеокопий первым выбирается 720p и сохраняется переключение на 1080p. Новые видеокопии автоматически не создаются.
- Worker отдаёт Range-запросы плеера фрагментами до 4 МиБ. Первые байты передаются сразу; параллельно ограниченная копия сохраняется в Cache API текущего узла Cloudflare на срок до часа. Одновременно сохраняются не более двух фрагментов на экземпляр, чтобы ограничить память. Кеш необязателен: его отказ не прерывает выдачу. Приватные предпросмотры, скачивания, изображения и запросы без stream=1 обходят этот механизм.
- Перед чтением кеша проверяются опубликованность media-записи, родительской публикации и актуальная ссылка на файл. Сохраняется прежний положительный кеш этих проверок до 15 секунд. Внутренние ключи кеша не являются публичными маршрутами. Успешный HTTP-каталог заранее заполняет тот же кеш опубликованных записей без продления исходного срока и в фоне подготавливает служебный токен чтения Drive; ответ каталога его не содержит.
- Добавлена `npm run diagnose:playback`: два чтения начального фрагмента первой песни/ролика из сети пользователя, времена заголовков/первых байтов/полного фрагмента, HIT/MISS. Токены и учётные данные не передаются и не выводятся.
