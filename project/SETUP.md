## 3. Cloudflare Workers Free

Создать бесплатный аккаунт, без платной подписки. 27 октября страница `https://dash.cloudflare.com/sign-up` остановилась на проверке «Подтвердите, что вы человек». Владелец сообщил об ошибке и решил зарегистрироваться позже сам со своего компьютера. Этот этап отложен; повторные попытки в облачном браузере не требуются. Подготовленный Worker не требует Cloudflare DNS и переноса nameserver домена: временного адреса `workers.dev` достаточно для медиа/API.

На своём компьютере с Node.js и npm выполнить:

```bash
npx wrangler login
npx wrangler whoami
```

`login` запускает OAuth-вход и открывает браузер. Эти команды авторизуют CLI; создание нового аккаунта и подтверждение почты при необходимости завершить в браузере. `whoami` проверяет, какой аккаунт подключён. [Официальная справка Wrangler](https://developers.cloudflare.com/workers/wrangler/commands/general/) проверена 27 октября 2026. Эта авторизация остаётся на компьютере владельца и не переносится в браузер чата. Пароль и токены сюда не нужны. Команды не публикуют Worker и не подключают платный план. Подключение ключей Диска, секрета почты и Turnstile остаётся следующим этапом.

Скопировать `worker/wrangler.example.jsonc` в рабочий `worker/wrangler.jsonc` и заполнить:

- `PROJECT_ID`, `ADMIN_UID` — реальный Firebase-проект и владелец;
- `ALLOWED_ORIGINS` — точные домены сайта и временного Firebase Hosting;
- `UPLOAD_FOLDER_ID` — созданная папка публикаций;
- `POLICY_VERSION` — та же версия, что в настройках сайта;
- `MAIL_RELAY_URL` — адрес опубликованного Apps Script.

Секреты Worker:

- `DRIVE_SERVICE_ACCOUNT_JSON` — JSON ключа сервисного аккаунта с чтением медиапапок;
- `FORM_SECRET` — случайный секрет подписи токена формы;
- `TURNSTILE_SECRET` — секрет защиты формы;
- `MAIL_RELAY_SECRET` — общий случайный секрет Worker и почтового обработчика.

Приватные ключи не входят в проект. При настройке вводить их через защищённый интерфейс или локальный CLI владельца. Сначала проверить `/health`, затем получить реальные медиа. Обработчик читает разрешение конкретного файла из Firestore и передаёт поток Диска с Range/CORS. Частный/неизвестный Drive ID сам по себе не даёт доступ. Разрешения и медиаответы имеют кэш не более 15 секунд.

Файлы новых публикаций связаны с документом песни, видео, фото или новости. Файл черновика не выдаётся посетителю; скрытие публикации закрывает выдачу в пределах 15 секунд. После замены файла старый адрес также перестаёт отдаваться через шлюз. В начальном каталоге связаны 87 аудиофайлов и 28 видео. Отдельные общие изображения, логотипы и пресс-материалы остаются в разрешённом списке общедоступных ресурсов. Эти ограничения не удаляют копию, которую посетитель уже скачал.

Файлы DOCX, RTF, PDF и ZIP пресс-кита отдаются только как скачивание. HTML/SVG/исполняемые файлы не допускаются в медиашлюз.

## Служебные инструменты

Все инструменты требуют закрытые ADC credentials вне проекта. Без `--apply` они не меняют внешнее состояние.

- `tools/firebase-cli.cjs` сохраняет обычные проверки CLI и учитывает существующий HTTPS proxy. Ключу SDK не хватает `serviceusage.services.get` для общей предварительной проверки CLI; правила были опубликованы через разрешённые операции Rules API без расширения IAM.
